aimet_onnx.peft¶

Note

This API is experimental and may change between releases.

aimet_onnx.peft adds one or more LoRA adapters to an ONNX model. The result runs like any other ONNX model, or can be quantized with AIMET. To quantize a model with adapters, see aimet_onnx.experimental.lora.

What is a LoRA adapter?¶

A LoRA adapter is a small add-on that changes what a model does without changing the model’s own weights. It is trained with the Hugging Face peft library and saved as a folder with two files:

my_adapter/
    adapter_config.json          # settings: rank (r), alpha, which layers it changes
    adapter_model.safetensors    # the adapter's weights

For each layer it changes, an adapter has two small weight matrices, A and B. The layer’s output becomes:

output = original_layer(x) + (x @ A) @ B * (alpha / r)

r (the rank) is the size of A and B. Both r and alpha come from adapter_config.json.

Quick start¶

import onnx
from aimet_onnx.peft import load_lora_adapters

base_model = onnx.load("base_model.onnx")

lora_model = load_lora_adapters(
    base_model,
    [("math", "adapters/math"), ("code", "adapters/code")],  # (name, adapter folder)
)

onnx.save(lora_model, "lora_model.onnx")

lora_model is an ordinary ONNX model: run it in onnxruntime, or pass it to aimet_onnx.QuantizationSimModel. base_model is not changed.

peft and safetensors must be installed.

What load_lora_adapters does¶

For every layer that an adapter changes, load_lora_adapters adds a small extra path next to the layer and adds its output to the layer’s output.

When you pass several adapters, they are all active at the same time, and their effects add up. If two adapters change the same layer, that layer gets one extra path that holds both adapters’ weights side by side. Its size r is the sum of their sizes. For example, adapters with r=4 and r=2 on the same layer give one path with r=6.

The names of the base model’s inputs, outputs and tensors stay the same. This matters for quantization: encodings computed on the base model can be loaded into the model with adapters.

To change which adapters are active or their scales, call load_lora_adapters again on the base model. You can’t add adapters to a model that already has them.

Note

The order of the adapters list decides where each adapter’s weights sit inside the shared path. If you reuse encodings across runs, always pass the adapters in the same order.

Preparing the base model¶

load_lora_adapters finds layers by name. An adapter refers to a layer as, for example, model.layers.0.self_attn.q_proj, and load_lora_adapters looks for an ONNX node with the same name.

  1. Export from PyTorch. Both torch.onnx.export(..., dynamo=False) and dynamo=True work. With dynamo=True the nodes get generic names, so fix them first:

    from aimet_onnx.prepare_passes.fix_node_names_in_dynamo_exported_onnx import (
    fix_node_names_pass,
)

base_model = fix_node_names_pass(base_model)

  2. Extra wrapper around the model. If the model was exported inside another module, every layer name may start with an extra model. (model.model.layers.0... instead of model.layers.0...). load_lora_adapters notices this, matches the names anyway, and logs a warning saying so.

  3. Smaller copy of the model. Adapter layers the model doesn’t have are skipped with a warning, as peft does in PyTorch. So an adapter trained on a 28-layer model works on a 2-layer copy for quick tests. If none of the adapter’s layers are in the model, it raises an error.

  4. Large models. Load the model without reading its weights into memory:

    base_model = onnx.load("base_model.onnx", load_external_data=False)

    The new model still points to the same weight files, so save it in the same folder as the base model (or copy the weight files next to it).

What is supported¶

Not supported

Layers

Linear (exported as MatMul or Gemm), Conv1d / Conv2d / Conv3d

LoRA

Other peft methods (IA3, prefix tuning, …)

Adapter settings

r, lora_alpha, target_modules, lora_dropout, init_lora_weights = True, False or "gaussian"

bias, use_rslora, use_dora, rank_pattern, alpha_pattern, modules_to_save, and any other setting changed from its default

Weights file

adapter_model.safetensors

adapter_model.bin (save with safe_serialization=True)

Number types

float32, float16 or float64. The adapter must use the same type as the base model

bfloat16 adapters. Nothing is converted for you; save the adapter with model.half() for a float16 base

If an adapter uses something that isn’t supported, load_lora_adapters raises an error that names the setting instead of producing a model that gives wrong results.

Adapters as model inputs¶

load_lora_adapters_as_inputs adds the same extra paths as load_lora_adapters, but their A and B weights and the scale are model inputs, so you switch adapters by feeding different inputs instead of rebuilding the model. It raises if the adapters have different layers, ranks or number types. See One set of encodings for every adapter (LoRA v1) for how to quantize such a model.
